LOT Git Workers: machines the tree cannot reach can help prove

Normally a LOT tree runs its sessions only on its own host (or in its own Slurm job). Git workers hand some obligations to another machine, and the two sides cannot reach each other over the network: all they share is one git remote. The tree stays the master and decides what goes out; a proof that comes back still has to pass the tree's gate.

1 · Compared with a local run

Locally, the controller drives sessions. Remotely, all handover happens through git branches.

Not every order lands: the other endings

untaken
No worker takes it within 5 minutes. The order is deleted and the obligation is the tree's; the tree resumes its paused sessions with their conversations kept.
Example: o002, o003; x0009–x0011 resumed at minute 32.7
withdrawn
The obligation no longer needs a proof (the tree proved its parent, or it was superseded). The tree deletes all three branches; the worker notices within one --poll and stops, pushing nothing.
Example: o009 (the tree proved o004 directly), o015 (o002 proved directly)
stale
The claim has had no heartbeat for 30 minutes. The tree takes the worker for gone and takes the obligation back.
gave-up / lease over
The worker pushes gave-up, or the lease (12 h by default) runs out. Either way the obligation is the tree's.
tree ends
Proved, deadline or cancelled: every order still out is withdrawn.

Hold-mode rules: no work done twice, none dropped

  • An obligation goes out at most once. If it comes back unproved, it stays with the tree for good.
  • For 5 minutes after it goes out (git_worker_wait) it belongs to the workers only. The tree pauses its own PROVE / DEC on it, starts no new ones, leaves it out of the preemption plan, and the gate refuses a lot offer of it from any other session (409).
  • An obligation the tree has already worked on for more than 5 minutes is never put out.
  • Only obligations at depth ≥ git_worker_min_depth, with all dependencies proved and not marked split-further, go out; the deepest first.
