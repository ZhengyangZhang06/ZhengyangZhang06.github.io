LOT Git Workers：让 tree 访问不到的机器也能帮忙证明

平时一棵 LOT tree 只在本机（或它自己的 Slurm 作业）里开 session。Git worker 把一部分 obligation 交给另一台机器，而且两边网络互不相通：唯一的共同点是一个 git remote。Tree 仍然是 master，决定发什么出去；交回来的证明照样要过 tree 的 gate。

1 · 和本地跑的区别

本地：controller 直接管 session。远程：只通过 git 分支交接。

不是每个 order 都落地：其余结局

untaken
5 分钟内没有 worker 领。order 删掉，归 tree；tree 恢复暂停的 session，对话保留，接着做。
实例：o002、o003，32.7 分钟时恢复 x0009–x0011
withdrawn
obligation 不再需要证明（tree 先证了上层，或它被 superseded）。tree 删掉三个分支，worker 在一个 --poll 内发现后停下，什么都不推。
实例：o009（o004 被 tree 直接证出）、o015（o002 被直接证出）
stale
claim 30 分钟没有 heartbeat，tree 认为 worker 已经没了，收回。
gave-up / lease 到期
worker 推 gave-up，或 lease（默认 12 h）用完。都归 tree。
tree 结束
不管是证完、到 deadline 还是取消，还在外面的 order 一律撤回。

hold 模式的规则：不重不漏

  • 一个 obligation 最多发出去一次。回来没证出的，永远留在 tree 这边。
  • 发出去之后 5 分钟（git_worker_wait）只归 worker；tree 暂停自己在这个 obligation 上的 PROVE / DEC，不开新的，抢占计划也不碰它，gate 拒绝其他 session 对它的 lot offer（409）。
  • tree 自己已经做了超过 5 分钟的 obligation 不会再发出去。
  • 只发深度 ≥ git_worker_min_depth、依赖已证完、没标记要继续拆的 obligation，最深的先发。
