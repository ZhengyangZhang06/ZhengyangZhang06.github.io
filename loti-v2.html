LOT-I v2 → v5 · informal option tree · 2026-11-10, updated 2026-11-24

An improvement tree: many agent sessions build one solver togetherImprovement tree：许多 agent session 合作构建一个求解器

LOT-I v2 lets many agent sessions improve one heuristic solver in parallel, on TCSExam solver tasks that have no formal statement and are scored on hidden instances. Sessions work on separate parts (slots) of competing architectures (variants); a trusted controller lands only changes that win a paired comparison, and the best variant is the champion. The example: AHC041 “Christmas tree cutting”, 12 hours, DeepSeek V4.1 Flash (1017) in every role.

LOT-I v2 让许多 agent session 并行改进同一个启发式求解器。任务来自 TCSExam 的求解器题：没有形式化陈述，按隐藏实例打分。 session 分别改进互相竞争的架构（variant）中的不同部件（slot）；可信的 controller 只合入在配对比较中胜出的修改，得分最高的变体就是 champion。示例：AHC041「Christmas tree cutting」， 12 小时，所有角色都用 DeepSeek V4.1 Flash (1017)。

Who does what分工

IMPROVEGets one slot and one idea; edits only that slot's files and submits small gains.分到一个 slot 和一个 idea，只改这个 slot 的文件，提交小的改进。
ARCHProposes a new variant: a glue file plus slots, each with a working stub and a frozen interface. From v3: two at once, each in its own direction.提出新变体：一个 glue 文件加若干 slot，每个 slot 有能跑的占位实现和固定接口。v3 起同时两个，各有方向。
AUDReviews a proposal; only an accepted one opens as a variant. From v3: it can also send the proposal back for revision (up to 3 rounds).审核提案，通过才成为变体。v3 起还可以退回修改（最多 3 轮）。
ControllerThe only writer of the integration branches. Every submission passes screen (builds, runs) → promote (paired comparison, more wins than losses) → hold-out (a new champion must not regress on unseen instances).唯一能写集成分支的进程。每次提交依次过 screen（能编译、能跑）→ promote（配对比较，胜多于负）→ hold-out（新 champion 在未见过的实例上不能退步）。
ChampionThe best variant's best commit: the deliverable at every moment.得分最高变体的最佳 commit，任何时刻的交付物。

What changed after v2 (v3–v5, 2026-11-17 to 11-24)v2 之后改了什么（v3–v5，2026-11-17 至 11-24）

Each change answers something we saw in a run.每一项都对应运行中实际遇到的问题。

change改动why原因
evalEvery evaluation is its own Slurm job: one CPU per instance, all instances at once. While a job waits for resources the tree pauses and the wait does not count.每次评测是独立的 Slurm 任务：每个实例一个 CPU，所有实例同时跑。等资源时整棵树暂停，等待时间不计入。One evaluator on 2 CPUs: a tw promote took 14 min, the evaluator was busy 95% of the time.原来只有 2 个 CPU 做评测：tw 一次 promote 要 14 分钟，评测 95% 的时间都在忙。
v3loti eval is the sessions' only measuring tool (high priority; says whether the gate would accept).loti eval 是 session 唯一的测量工具（高优先级，直接告诉它能否过门）。Sessions built their own scorers and timing harnesses: local timings on shared CPUs are noise.session 自己造评分器和计时工具；共享 CPU 上的本地计时全是噪声。
v3Small but consistent gains land: gain > 0.0002 and sign test p ≤ 0.01.小而稳定的提升也能合入：提升 > 0.0002 且符号检验 p ≤ 0.01。26 wins / 4 losses was rejected for a +0.0009 mean near K.接近最优时，26 胜 4 负因平均只提升 0.0009 被拒。
v3An idea that landed, or failed twice, is not handed out again.已合入或失败两次的 idea 不再分配。Sessions were given ideas already in the code.session 拿到的 idea 早已在代码里。
v3Review loop: AUD answers approve, revise or reject; a revision goes back to the same ARCH session and the same reviewer checks it (up to 3 rounds).审核循环：AUD 给出通过 / 修改 / 拒绝；修改意见交回同一个 ARCH session，由同一个审核者复核（最多 3 轮）。13 of 16 proposals were rejected, many “fixable in one pass”.16 个提案拒了 13 个，很多是「一轮就能修好」。
v3Two ARCH sessions at once, each given its own direction (core search, stages, instance split, exact parts, portfolio, performance, free).同时两个 ARCH，各分一个方向（核心搜索、分阶段、拆实例、精确子问题、组合策略、性能、自由）。New architectures won later champions; parallel ARCHs proposed the same split.后期 champion 多来自新架构；并行的 ARCH 容易想到同一种拆法。
v4A revision is bound to its proposal when the request arrives, not when the gate finishes.修改版在请求到达时就绑定到原提案，而不是等检查结束。The gate took up to 3 h on glasscut; revisions were dropped and one session made two proposals.glasscut 的架构检查要 3 小时，修改版被误判作废，还出现了重复提案。
v5Each session runs in its own PID namespace.每个 session 运行在独立的 PID 命名空间里。A session's pkill -f "python3 -" killed two controllers.一个 session 的 pkill -f "python3 -" 杀掉了两个 controller。
v5Hold-out: one new failure is tolerated if the mean does not drop; a failure is explained to the sessions (size class, time, value) without naming the instance.hold-out：平均分不降时容忍 1 个新失败；失败原因（规模、用时、解的质量）告诉 session，但不透露实例。One fragile hold-out instance kept a better tw solver out for 14 h.一个脆弱的 hold-out 实例把更好的 tw 求解器挡了 14 小时。
v5The architecture gate allows a lag of 0.15 + 0.5 × (1 − champion mean).架构检查允许落后 0.15 + 0.5 ×（1 − champion 均分）。Every curriculum proposal failed a fixed 0.15 lag.固定 0.15 时 curriculum 的提案全部过不了。
